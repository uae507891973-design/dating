# Стадия 0 — Подготовка и фундамент (детально)

**Длительность:** ~4 недели (2 спринта). **Команда:** product, дизайнер, 2 backend, 1 mobile/web, 1 ML/data, OPS (частично), юрист (внешний).
**Цель стадии:** снять ключевые продуктовые, юридические и технические риски до написания продуктового кода; получить рабочую инфраструктуру и проверенный прототип.

Опорные документы: [исследование рынка](../../research/dating-market-ru.md), [исследование функций](../../research/feature-research-matching-video.md), [план реализации](../implementation-plan.md).

## Спринт 0.1 — Discovery, требования, дизайн

### 0.1.1 CustDev-исследование
- Рекрутинг 10–15 респондентов из ядра аудитории (28–45 лет, цель — серьёзные отношения), баланс по полу.
- Гайд интервью: текущий опыт дейтинга, боли (боты, поверхностность, недоверие), отношение к тесту совместимости, к объяснимому подбору, к видеознакомству «вслепую», готовность платить.
- Синтез: карта болей, JTBD (jobs-to-be-done), персоны, проверка гипотез.
- **Артефакт:** отчёт CustDev + обновлённые персоны.
- **AC:** каждая ключевая гипотеза письменно подтверждена/опровергнута на основе ≥10 интервью.

### 0.1.2 Продуктовые требования
- Список фич MVP с приоритизацией MoSCoW (Must/Should/Could/Won't).
- Метрики и трекинг-план (события и их свойства).
- Определение North Star (взаимные качественные мэтчи) и вспомогательных метрик по стадиям.
- **Артефакт:** PRD (product requirements document) MVP.

### 0.1.3 Юридический и комплаенс-контур
- Карта требований 152-ФЗ: где хранятся ПДн, какие согласия нужны, политика конфиденциальности, пользовательское соглашение.
- Контент-политика «без пошлости» (что запрещено, как модерируется, апелляции), возрастной ценз 18+.
- Требования 54-ФЗ к будущим платежам (фискализация) — заложить в архитектуру.
- **Артефакт:** комплаенс-чек-лист, проекты согласий и политик.

### 0.1.4 Дизайн и прототип
- Дизайн-система: палитра, типографика, компоненты, тон бренда (доверие, тепло, без пошлости).
- Кликабельный прототип (Figma): онбординг → тест совместимости → анкета → подборка с объяснениями.
- Юзабилити-тест прототипа на ≥5 респондентах.
- **AC:** прототип проходит базовые сценарии без критических затыков; правки внесены.

## Спринт 0.2 — Архитектура, данные, инфраструктура

### 0.2.1 Архитектура системы
- Сервисное разбиение (модульный монолит на старте, разделяемый по доменам): `auth`, `profile`, `psychotest`, `matching`, `chat`, `media`, `moderation`, `payments` (заглушка), `analytics`.
- Решения: синхронные REST для CRUD, WebSocket для чата/звонков, очередь задач (например, для модерации медиа).
- Нефункциональные требования: P95 latency подбора < 300 мс, доступность 99.5%, шифрование PII.
- **Артефакт:** документ архитектуры (C4-диаграммы: контекст, контейнеры).

### 0.2.2 Модель данных (стартовая схема)
Ключевые таблицы (PostgreSQL):

| Таблица | Поля (основные) |
|---|---|
| `users` | id, phone, email, password_hash?, status, role, created_at, last_active_at |
| `profiles` | user_id, display_name, birth_date, gender, looking_for, geo (PostGIS point), city, bio, intent (marriage/relationship/friendship) |
| `interests` / `profile_interests` | справочник интересов и связь many-to-many |
| `psychotest_questions` | id, текст, категория, тип ответа, веса |
| `psychotest_answers` | user_id, question_id, value, importance |
| `psychoprofiles` | user_id, vector (jsonb/pgvector), updated_at |
| `photos` | id, user_id, url, is_primary, moderation_status, moderated_at |
| `verifications` | id, user_id, type (selfie), status, created_at |
| `likes` | from_user, to_user, type (like/skip), created_at |
| `matches` | id, user_a, user_b, created_at, status |
| `messages` | id, match_id, sender_id, body, status, created_at |
| `reports` / `blocks` | автор, цель, причина, статус |
| `consents` | user_id, doc_version, accepted_at |
| `audit_log` | actor, action, target, timestamp |

- **Артефакт:** ER-диаграмма + миграции.

### 0.2.3 Контракты API
- OpenAPI-спека для MVP-эндпоинтов (auth, profile, psychotest, media, verify).
- Соглашения: формат ошибок, пагинация, версионирование (`/v1`), идемпотентность.
- **Артефакт:** `openapi.yaml` (черновик MVP).

### 0.2.4 Инфраструктура и каркас
- **OPS:** РФ-облако (Yandex/VK Cloud), окружения dev/stage/prod, управление секретами, доменные имена/SSL.
- **OPS:** CI/CD: линт → тесты → сборка → деплой на stage; ручной promote на prod.
- **BE:** каркас API, подключение БД, миграции, Redis, healthcheck.
- **FE:** каркас React Native + Next.js, навигация, дизайн-токены, сетевой слой, обработка ошибок/локализация (ru).
- **ML/OPS:** ClickHouse + сбор событий по трекинг-плану; дашборд «воронка регистрации».
- **AC:** «скелет» приложения собирается и деплоится через CI на stage; событие `registration_started` долетает в аналитику; healthcheck зелёный.

## Результаты стадии 0 (Deliverables)
1. Отчёт CustDev + персоны + PRD MVP.
2. Комплаенс-чек-лист, проекты согласий и политик (152-ФЗ, контент-политика, 18+).
3. Дизайн-система + протестированный прототип.
4. Документ архитектуры, ER-диаграмма, OpenAPI-черновик.
5. Развёрнутая инфраструктура (dev/stage/prod), CI/CD, аналитика.

## Definition of Done стадии
- Гипотезы проверены; MVP-скоуп зафиксирован.
- Прототип протестирован на ≥5 пользователях.
- Инфраструктура и каркас работают; деплой через CI; первое событие в аналитике.
- Юр-контур согласован, риски 152-ФЗ покрыты планом.

## Риски стадии и реакция
| Риск | Реакция |
|---|---|
| Гипотезы не подтверждаются | скорректировать скоуп/позиционирование до старта разработки |
| Недооценка требований 152-ФЗ | ранний аудит с юристом, выбор РФ-провайдеров |
| Размытый MVP-скоуп | жёсткий MoSCoW, фиксация «Won't» |
