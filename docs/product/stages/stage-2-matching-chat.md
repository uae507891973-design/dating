# Стадия 2 — Мэтчинг и общение (детально)

**Длительность:** ~6 недель (3 спринта). **Цель:** доказать гипотезу совместимости — пользователи получают релевантные пары, видят честные объяснения и общаются.

Дифференциатор стадии: **объяснимый мэтчинг** (см. [исследование функций](../../research/feature-research-matching-video.md)).

---

## Спринт 2.1 — Движок подбора

### Архитектура подбора (две стадии)
1. **Кандидатогенерация (recall):** жёсткие фильтры — пол/looking_for, возрастной диапазон, гео-радиус (PostGIS), активность, не заблокирован, не показан недавно.
2. **Ранжирование (precision):** скоринг совместимости из Стадии 1 + бонусы (общие интересы, совпадение намерения, свежесть активности, верификация).

### Формула скоринга (стартовая)
```
score = w1*test_overlap(importance) + w2*interest_overlap
      + w3*intent_match + w4*activity_recency + w5*verified_bonus
```
- `test_overlap` — взвешенное по важности пересечение ответов теста (ядро совместимости).
- веса калибруются на бете; хранится вклад каждого компонента для объяснений.

### Задачи
- **ML/BE:** сервис рекомендаций; кэш кандидатов в Redis; пагинация подборки.
- **BE:** лайки/пропуски (`likes`), образование `match` при взаимности; защита от повторных показов.
- **FE:** экран подборки (карточки с фото, % совместимости — заглушка до 2.2), действия лайк/пропуск.
- **Analytics:** `card_viewed`, `like`, `skip`, `match_created`.

### Acceptance Criteria
- Подбор отдаёт релевантных кандидатов, P95 < 300 мс.
- Мэтч образуется при взаимном лайке; дубли не показываются.
- Вклад компонентов скоринга сохраняется (для объяснений).

> Примечание: искусственный лимит «slow dating» НЕ внедряется (исключён ранее). Используется обычная подборка/лента.

## Спринт 2.2 — Объяснимый мэтчинг (ключевой дифференциатор)

### Задачи
- **ML/BE:** генератор объяснений (rule-based): из вкладов скоринга выбрать топ-2–3 фактора и сформулировать причины человекочитаемо.
  - Примеры: «Общие ценности: семья, ЗОЖ», «Обе цели — долгие отношения», «5 общих интересов».
- **BE:** % совместимости на карточке (нормализованный score).
- **BE:** **scrutability** — пользователь отмечает факторы «важно / не важно»; пересчёт скоринга и подборки.
- **FE:** блок «Почему вы подходите» (2–3 причины) + % совместимости; UI управления важностью факторов.
- **ML/QA:** A/B-инфраструктура: вариант «с объяснениями» vs «без»; логирование исходов (отклик, мэтч, диалог).

### Принципы (из исследования)
- Объяснения **честные** — отражают реальные факторы скоринга (иначе теряется доверие).
- Лаконичные, позитивные, конкретные; не «вы оба лайкнули X».

### Acceptance Criteria
- На карточке отображаются % и 2–3 честные причины, соответствующие скорингу.
- Отметки важности влияют на подбор (проверено).
- A/B измеряет влияние объяснений на отклик и доходимость до диалога.

## Спринт 2.3 — Чат и первый контакт

### Задачи
- **BE:** real-time чат на WebSocket; хранение `messages`; статусы доставлено/прочитано; пагинация истории; пуш при оффлайне.
- **ML/BE:** айсбрейкеры — подсказки первого сообщения на основе общих интересов/ценностей (генерируются при открытии чата).
- **BE:** модерация переписки по сигналам (спам/скам/ссылки), репорт прямо из чата, ограничение для неверифицированных (антиспам).
- **FE:** экран чата, индикаторы статусов, блок айсбрейкеров, действия «пожаловаться/заблокировать».
- **Analytics:** `chat_opened`, `first_message_sent`, `message_reply`, `icebreaker_used`.

### API (пример)
- WS-канал `/v1/chat` (события message/typing/read)
- `GET /v1/matches/{id}/messages`
- `POST /v1/matches/{id}/messages`

### Acceptance Criteria
- Сообщения доставляются real-time; статусы корректны.
- Ответ на первое сообщение ≥40%; ≥1 качественный мэтч на активного пользователя в неделю.
- Айсбрейкеры показываются и используются; репорт/блок из чата работают.

---

## Результаты стадии 2 (Deliverables)
1. Рабочий цикл подбор → мэтч → чат.
2. Объяснимый мэтчинг (% + причины + scrutability) с A/B.
3. Айсбрейкеры и модерация чата.

## Definition of Done стадии / Gate
- Цикл подтверждён метриками: отклик ≥40%, ≥1 мэтч/польз./нед.
- A/B показывает положительный (или нейтральный с ростом доверия) эффект объяснений.
- Производительность подбора в пределах SLA.

## Тест-план
- Unit: генератор объяснений (соответствие вкладам скоринга), пересчёт при scrutability.
- Integration: лайк→мэтч→чат, доставка WS-сообщений.
- Load: подбор и чат под нагрузкой; latency.
- A/B-валидация корректности разбиения и метрик.

## Риски и реакция
| Риск | Реакция |
|---|---|
| Мало релевантных кандидатов (холодный старт) | расширять радиус/фильтры, посев аудитории (Стадия 5) |
| «Фальшивые» объяснения подрывают доверие | строго rule-based из реальных факторов |
| Спам/скам в чате | лимиты для неверифицированных, сигналы, репорт |
