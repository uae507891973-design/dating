# Поэтапный план работ (по итогам аудита и security-ревью)

Документ объединяет находки [security-ревью](../security/security-review.md) (S1–S14)
и [аудита продукта](./product-audit.md) (F1–F11, U1–U7) в приоритизированную
дорожную карту. Каждый этап — с задачами, критериями готовности (DoD) и оценкой.

Принцип очерёдности: сначала то, что делает запуск небезопасным или неработающим,
затем — стабилизация, затем — рост. Стадии 4–5 плана продукта (монетизация, рост)
идут после закрытия блокеров.

Легенда усилий: S ≈ 0.5–1 д · M ≈ 2–3 д · L ≈ 4–5 д.

## Этап A — Критические блокеры безопасности ✅ ВЫПОЛНЕНО

| # | Задача | Источник | Усилие | Статус |
|---|--------|----------|--------|--------|
| A1 | Убрать OTP-код и телефон из логов; маскирование ПДн | S1, S5 | S | ✅ |
| A2 | Guard на старте: падать при дефолтном/коротком `jwt_secret` в prod | S2 | S | ✅ |
| A3 | Отключить `echo`/`debug` в prod; не логировать SQL с ПДн | S3 | S | ✅ |
| A4 | Централизованная проверка блокировки в like / message / video | S4 | M | ✅ |
| A5 | 6-значный OTP; сброс попыток при новом коде; не удалять код жертвы | S10 | M | ✅ |

**DoD этапа A — выполнено:** код не логируется (маскирование `mask_phone`,
опциональный `otp_debug_log` только вне prod); `validate_prod_settings` не даёт
стартовать prod с дефолтным/коротким секретом, `debug` или `otp_debug_log`;
SQL-эхо выключено в prod; блокировка запрещает like/message/video в обе стороны;
OTP 6-значный, чужие попытки не удаляют код жертвы (recovery через новый код).
Покрыто тестами (`tests/test_security_hardening.py`), всего 67 тестов зелёные.

## Этап B — Высокие риски и «сломанное» ✅ ВЫПОЛНЕНО

| # | Задача | Источник | Усилие | Статус |
|---|--------|----------|--------|--------|
| B1 | Раздача фото (`StaticFiles`) + валидация по сигнатуре (magic-bytes) | S8, F1 | M | ✅ |
| B2 | Ротация refresh + `token_version`; `POST /auth/logout` | S6, F4 | M | ✅ |
| B3 | Rate-limit OTP по IP; защита от SMS-pumping | S7 | M | ✅ |
| B4 | Гео-фильтр подбора по радиусу (`max_distance_km`, haversine; PostGIS на проде) | F2 | M | ✅ |
| B5 | Гейт заполнения анкеты + фильтр кандидатов без психопрофиля | F5, F6 | M | ✅ |

**DoD этапа B — выполнено:** фото раздаются (`/media`) и принимаются только реальные
изображения (сигнатура); `logout` инвалидирует все токены (`token_version`), refresh
проверяет версию; OTP лимитируется по IP; подбор фильтрует по радиусу и требует
заполненной анкеты + пройденного теста, скрывает кандидатов без психопрофиля.
Покрыто тестами; всего 73 теста зелёные.

## Этап C — Комплаенс 152-ФЗ и приватность ✅ ВЫПОЛНЕНО (C2 — операционный)

| # | Задача | Источник | Усилие | Статус |
|---|--------|----------|--------|--------|
| C1 | Шифрование PII в покое (AES-SIV, ключ из `PII_SECRET`; в prod — KMS) | S3, S9 | L | ✅ |
| C2 | Хранение ПДн на инфраструктуре РФ | S9 | M | ⏳ деплой |
| C3 | Повторное согласие при смене версии документа | S14, F11 | M | ✅ |
| C4 | Тексты юр-документов + отдача из API | U4 | S | ✅ |

**DoD этапа C:** телефон/почта шифруются в покое (детерминированный AES-SIV —
поиск и уникальность работают, доказано тестом «сырое значение ≠ открытый телефон»);
при росте версии документа `/v1/legal/pending` показывает недостающие, подбор
блокируется (403 `reconsent_required`) до `/v1/legal/reconsent`; тексты документов
доступны через `/v1/legal/documents/{type}`. C2 (РФ-хостинг) — настройка окружения
при деплое. 77 тестов зелёные.

## Этап F — Продолжение продуктовых стадий
После закрытия блокеров и стабилизации — возврат к плану развития:
- **Стадия 4 — Монетизация:** подписка/платежи РФ (ЮKassa/RuStore, 54-ФЗ),
  микротранзакции, paywall-эксперименты.
- **Стадия 5 — Рост:** рефералы, регионы/холодный старт, ML-скоринг + SHAP,
  партнёрства.

## Сводная последовательность и вехи

```
Спринт 1  →  A (крит. безопасность)            ← блокер релиза
Спринт 2  →  B (высокие риски + «сломанное»)    ← готовность закрытой беты
Спринт 3  →  C (152-ФЗ / приватность)           ← юридическая готовность
Спринт 4  →  D (стабилизация/производительность) ← готовность открытой беты
Спринт 5  →  E (юзабилити)                       ← полировка
Далее     →  F (Стадии 4–5: монетизация, рост)
```

| Веха | Что достигнуто |
|------|----------------|
| M1 (после A) | Нет утечек секретов; блокировка защищает; безопасно для закрытого теста |
| M2 (после B) | Всё заявленное работает; готовность закрытой беты |
| M3 (после C) | Соответствие 152-ФЗ; можно расширять аудиторию |
| M4 (после D) | Готовность открытой беты (масштаб, мониторинг) |
| M5 (после E) | Отполированный UX; конверсия онбординга |

## Рекомендация по старту
Начать с **Этапа A** — это быстрые (S/M) и самые важные фиксы: код в логах,
JWT-guard, обход блокировки, телефон в логах. Каждая задача — с юнит/интеграционным
тестом, чтобы регрессия не вернулась.
