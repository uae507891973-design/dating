# Подробные этапы реализации

Детализация [поэтапного плана разработки](./development-plan.md): каждая стадия разложена на конкретные рабочие шаги — задачи, модель данных, API/экраны, технические детали и критерии приёмки (Acceptance Criteria, AC).

Легенда: **BE** — backend, **FE** — клиент (mobile/web), **ML** — данные/алгоритмы, **OPS** — инфраструктура, **DES** — дизайн, **QA** — тестирование.

---

## Стадия 0 — Подготовка и фундамент

### Этап 0.1. Discovery и требования
1. **DES/Product:** провести 10–15 CustDev-интервью (ядро 28–45 лет); зафиксировать боли, гипотезы, ценности.
2. **Product:** проверить гипотезы — объяснимый мэтчинг и видео «вслепую» (готовность платить, восприятие безопасности).
3. **Product:** сформировать список фич MVP и приоритеты (MoSCoW).
4. **Юрист/Product:** карта требований 152-ФЗ, контент-политика «без пошлости», возрастной ценз 18+.
5. **DES:** кликабельный прототип (Figma): онбординг, тест, анкета, подборка.
   - **AC:** прототип протестирован на ≥5 респондентах; гипотезы подтверждены/опровергнуты письменно.

### Этап 0.2. Архитектура и схема данных
1. **BE:** выбрать стек (по плану реализации), описать сервисную архитектуру (auth, profile, matching, chat, media, moderation, payments).
2. **BE:** ER-диаграмма. Базовые сущности:
   - `users` (id, phone/email, статус, роль, created_at)
   - `profiles` (user_id, имя, дата рождения, пол, гео, bio, цели)
   - `psychotest_answers` (user_id, question_id, value, importance)
   - `psychoprofile` (user_id, вектор черт/ценностей)
   - `photos` (id, user_id, url, moderation_status)
   - `verifications` (user_id, тип, статус, дата)
   - `likes`, `matches`, `messages`, `reports`, `blocks`
3. **BE:** контракт API (OpenAPI), соглашения по версионированию и ошибкам.
   - **AC:** ER-диаграмма и OpenAPI согласованы; ревью архитектуры пройдено.

### Этап 0.3. Инфраструктура и каркас
1. **OPS:** РФ-хостинг (Yandex/VK Cloud), окружения dev/stage/prod.
2. **OPS:** Docker-образы, CI/CD (линт, тесты, сборка, деплой), секреты.
3. **BE:** каркас API + миграции БД (PostgreSQL+PostGIS) + Redis.
4. **FE:** каркас React Native + Next.js, навигация, дизайн-токены, единый клиент API.
5. **ML/OPS:** ClickHouse + трекинг-план событий (registration, onboarding_step, like, match, message, verify).
   - **AC:** «пустое» приложение собирается и деплоится через CI на stage; событие регистрации долетает в аналитику.

## Стадия 1 — MVP-ядро

### Этап 1.1. Регистрация и аккаунт
- **BE:** регистрация/логин по телефону (SMS-провайдер РФ) и email; JWT/refresh-сессии; rate-limit.
- **BE:** хранение PII с шифрованием в покое; восстановление доступа.
- **FE:** экраны входа/регистрации, ввод OTP, согласия на обработку ПДн (152-ФЗ) в потоке.
- **QA:** негативные кейсы (неверный код, повтор, бан-лист).
- **AC:** пользователь регистрируется и повторно входит; согласия зафиксированы с таймстампом; PII зашифрована.

### Этап 1.2. Онбординг и тест совместимости
- **ML/Product:** разработать тест 16–20 вопросов (с психологом): ценности, цели, образ жизни; шкала важности на каждый вопрос.
- **BE:** хранение ответов (`psychotest_answers`), расчёт `psychoprofile` (вектор по категориям).
- **FE:** геймифицированный мастер с прогресс-баром; выбор **намерения** (брак / долгие отношения / дружба).
- **ML:** алгоритм скоринга совместимости (заготовка для Стадии 2): cosine/weighted-overlap по совпавшим ответам с учётом важности.
- **AC:** completion теста ≥70%; psychoprofile формируется; намерение сохраняется.

### Этап 1.3. Анкета и модерация контента
- **BE:** CRUD анкеты (фото, bio, интересы, параметры); объектное хранилище РФ для медиа.
- **ML/BE:** интеграция NSFW-классификатора (авто-модерация фото) + статусы `pending/approved/rejected`.
- **BE:** ручная модераторская очередь и панель (просмотр, approve/reject, причины).
- **FE:** редактор анкеты, загрузка фото, статусы модерации для пользователя.
- **AC:** откровенный/запрещённый контент отклоняется (авто + ручная проверка); approved-фото видны в подборке.

### Этап 1.4. Верификация и базовая безопасность
- **BE/ML:** селфи-верификация (liveness + сверка с фото профиля); статус и бейдж Verified.
- **BE:** жалобы (`reports`) и блокировки (`blocks`); аудит-логи доступа к данным.
- **FE:** поток верификации, индикатор Verified, кнопки «пожаловаться/заблокировать».
- **QA/Security:** проверка хранения данных, прав доступа, базовый pentest.
- **AC:** доля верифицированных ≥60% в закрытой бете; жалоба/блок работают; есть аудит-логи.

**Gate Стадии 1:** регистрация→тест→анкета→верификация работает end-to-end; готовность к закрытой бете.

## Стадия 2 — Мэтчинг и общение

### Этап 2.1. Движок подбора
- **ML:** финализировать скоринг: совпадения теста (с важностью) + общие интересы + совпадение намерений + гео (PostGIS-радиус) + фильтры (возраст/пол/город).
- **BE:** сервис рекомендаций; кандидатогенерация (фильтры) → ранжирование (скоринг); кэш в Redis.
- **BE:** лайки/пропуски, образование `match` при взаимности; дедуп показанных.
- **FE:** экран подборки/ленты с карточками; действия лайк/пропуск.
- **AC:** подбор отдаёт релевантных кандидатов < 300 мс; мэтч создаётся при взаимном лайке.

### Этап 2.2. Объяснимый мэтчинг (дифференциатор)
- **ML/BE:** генератор объяснений (rule-based): топ-2–3 фактора совпадения (ценности, цель, интересы) + % совместимости.
- **BE:** scrutability — отметка факторов «важно / не важно», пересчёт скоринга.
- **FE:** блок «% совместимости» + причины «Почему вы подходите» на карточке; UI для важности факторов.
- **ML/QA:** A/B-инфраструктура: «с объяснением» vs «без»; логирование исходов.
- **AC:** объяснения честные (отражают реальные факторы скоринга); A/B измеряет влияние на отклик/мэтчи.

### Этап 2.3. Чат
- **BE:** real-time чат (WebSocket), хранение `messages`, статусы доставки/прочтения, пагинация истории.
- **ML/BE:** айсбрейкеры на основе общих интересов/ценностей (подсказки для первого сообщения).
- **BE:** модерация переписки по сигналам (спам/скам), репорт из чата.
- **FE:** экран чата, индикаторы статусов, подсказки-айсбрейкеры.
- **AC:** доставка сообщений real-time; ответ на первое сообщение ≥40%; ≥1 качественный мэтч/польз./нед.

**Gate Стадии 2:** цикл подбор→мэтч→чат с объяснениями подтверждён метриками и A/B.

## Стадия 3 — Доверие, видео и антифрод

### Этап 3.1. Антифрод-движок
- **ML:** поведенческие признаки (скорость лайков/сообщений, шаблонность текста, дубли устройств/IP, аномалии).
- **BE:** скоринг риска профиля → авто-флаги в модераторскую очередь; внутренний trust-score (без публичной шкалы).
- **BE:** правила реакции (ограничение, шадоу-бан, ручная проверка).
- **AC:** доля ботов/скам-аккаунтов снижается; ложноположительные под контролем (метрика precision/recall на размеченной выборке).

### Этап 3.2. Видеознакомство «вслепую» (дифференциатор)
- **OPS/BE:** RTC-провайдер РФ / WebRTC-инфраструктура (TURN/STUN), сигналинг.
- **BE/FE:** опциональный 3-мин блюр-видеозвонок после мэтча; управление блюром у получателя; таймер.
- **BE/FE:** встроенные айсбрейкеры; продолжение/раскрытие по обоюдному «да».
- **Security:** без обмена контактами; защита от записи; репорт из звонка; авто-модерация кадра (NSFW).
- **ML:** успешный видеоконтакт → сигнал «живой человек» в trust-score/антифрод.
- **AC:** звонок стабилен; продолжают после видео ≥50%; репорт/модерация работают.

### Этап 3.3. Стабилизация и открытая бета
- **BE/FE:** push-уведомления (мэтч, сообщение, звонок).
- **OPS/QA:** нагрузочное тестирование, оптимизация, мониторинг/алерты.
- **Security:** аудит безопасности и приватности; проверка 152-ФЗ перед публичным запуском.
- **AC:** пройден аудит; стабильность под нагрузкой; открытая бета запущена.

## Стадия 4 — Монетизация

### Этап 4.1. Платежи и подписка
- **BE:** интеграция платёжного провайдера РФ (ЮKassa/CloudPayments) + RuStore-биллинг; вебхуки статусов.
- **BE:** подписка ~399–599 ₽/мес: приоритет анкеты, безлимит сообщений, расширенные фильтры; продления; фискализация (54-ФЗ).
- **FE:** экраны тарифов, оплата, управление подпиской.
- **AC:** оплата/продление/отмена работают; чеки формируются; доступ к премиум-фичам по статусу.

### Этап 4.2. Пакеты и эксперименты
- **BE/FE:** микротранзакции (буст, подсветка, суперлайк); кошелёк/баланс.
- **Product:** этичная монетизация — премиум за качество (расширенная совместимость/верификация), не только «pay-to-see-likes».
- **ML/QA:** paywall-эксперименты, аналитика конверсии/churn/ARPPU.
- **AC:** conversion to paid 3–5%; churn < 10%/мес; дашборды выручки.

## Стадия 5 — Рост и масштаб

### Этап 5.1. Привлечение и удержание
- **BE/FE:** реферальная программа (инвайты, бонусы), измерение K-фактора.
- **Product/FE:** контент-маркетинг и SEO (блог на Next.js о здоровых отношениях).
- **Product:** меры против гендерного перекоса (women-first фичи, бесплатные функции дефицитному сегменту).
- **AC:** K-фактор > 0; рост органического трафика.

### Этап 5.2. Регионы и «холодный старт»
- **Product/OPS:** поэтапный запуск по городам, посев аудитории; локальные подборки.
- **AC:** жизнеспособная плотность аудитории в новых городах (мэтчи/польз. не падают).

### Этап 5.3. ML-зрелость
- **ML:** переход от rule-based к ML-скорингу с SHAP-атрибуцией объяснений.
- **ML:** постматч-обратная связь («совпало ли описание с реальностью») → дообучение модели и борьба с фейками.
- **AC:** ML-подбор превосходит rule-based в A/B по доходимости до диалога/свидания.

### Этап 5.4. Партнёрства
- **Product:** психологи (контент/консультации), оффлайн-события — мост онлайн→офлайн.
- **AC:** запущены первые партнёрства; измерен вклад в удержание.

**Gate Стадии 5:** LTV/CAC > 3, устойчивый рост MAU и доли успешных свиданий.

## Сквозные задачи (выполняются во всех стадиях)
- **152-ФЗ/безопасность:** хранение ПДн в РФ, шифрование, согласия, аудит-логи, бэкапы, регулярные проверки доступа.
- **Модерация:** AI + ручная очередь, политика «без пошлости», 18+, эскалации.
- **Аналитика:** трекинг событий, продуктовые дашборды, A/B-платформа.
- **QA:** unit/integration/e2e-тесты, регресс, нагрузочное тестирование.
- **Поддержка:** каналы обращений, SLA на жалобы, разбор инцидентов.

## Порядок зависимостей (критический путь)
0.2 (схема данных) → 0.3 (инфраструктура) → 1.1 (аккаунт) → 1.2 (тест) → 1.3/1.4 (анкета/верификация) → 2.1 (подбор) → 2.2 (объяснения) → 2.3 (чат) → 3.1 (антифрод) → 3.2 (видео) → 4 (монетизация) → 5 (рост).

> Примечание: исключённые ранее идеи (slow dating, публичная шкала доверия, safety-кит свидания) в этих этапах не реализуются — вместо них обычная подборка без искусственного лимита и внутренний trust-score без публичной шкалы.
