# Стадия 1 — MVP-ядро (детально)

**Длительность:** ~8 недель (4 спринта). **Цель:** провести пользователя по пути регистрация → тест совместимости → анкета → верификация и подготовить закрытую бету.

Опорные решения: ядро 28–45, фокус на серьёзные отношения, доверие/безопасность в основе, объяснимый мэтчинг закладывается уже здесь (скоринг — заготовка для Стадии 2).

---

## Спринт 1.1 — Регистрация и аккаунт

### Задачи
- **BE:** регистрация/логин по телефону (SMS-OTP через РФ-провайдера) и email; JWT access + refresh; rate-limit и защита от перебора OTP.
- **BE:** шифрование PII в покое (телефон/email), хеширование паролей (если email-флоу), ротация ключей.
- **BE:** учёт согласий (`consents`) с версией документа и таймстампом.
- **FE:** экраны: приветствие, ввод телефона, ввод OTP, согласия (152-ФЗ), создание базового аккаунта.
- **FE:** обработка ошибок (неверный код, истёк код, лимит попыток).
- **QA:** негативные кейсы, ретраи OTP, бан-лист.

### API (пример)
- `POST /v1/auth/request-otp` → отправка кода
- `POST /v1/auth/verify-otp` → выдача токенов
- `POST /v1/auth/refresh` → обновление токена
- `POST /v1/consents` → фиксация согласий

### Acceptance Criteria
- Регистрация и повторный вход работают; refresh-токен продлевает сессию.
- Согласия зафиксированы с версией и временем; без согласия регистрация недоступна.
- PII зашифрована; OTP защищён лимитами.

## Спринт 1.2 — Онбординг и тест совместимости

### Задачи
- **ML/Product (с психологом):** разработать тест 16–20 вопросов по категориям: ценности, цели/намерения, образ жизни, отношение к семье, коммуникация. На каждый вопрос — ответ + важность (low/medium/high).
- **BE:** хранение вопросов (`psychotest_questions`), ответов (`psychotest_answers`); расчёт `psychoprofiles` — вектор по категориям (нормализованные веса).
- **ML:** функция совместимости (заготовка): взвешенное пересечение ответов с учётом важности (модель OkCupid-подобного match%); вернуть score 0–100 + вклад категорий (для будущих объяснений).
- **FE:** мастер онбординга с прогресс-баром, анимациями, возможностью вернуться; экран выбора **намерения**.
- **Analytics:** события `onboarding_step`, `test_completed`.

### Модель ответа теста
```
psychotest_answers: { user_id, question_id, value, importance }
psychoprofiles: { user_id, vector: { values: .., goals: .., lifestyle: .. }, updated_at }
```

### Acceptance Criteria
- Completion теста ≥70%; psychoprofile рассчитывается и сохраняется.
- Намерение (брак/отношения/дружба) сохранено и доступно мэтчингу.
- Функция совместимости возвращает score + вклад категорий (проверено юнит-тестами).

## Спринт 1.3 — Анкета и модерация контента

### Задачи
- **BE:** CRUD анкеты (display_name, birth_date, gender, looking_for, city/geo, bio, interests, до N фото).
- **OPS/BE:** объектное хранилище РФ для медиа; генерация превью; CDN.
- **ML/BE:** интеграция NSFW-классификатора — авто-модерация при загрузке фото; статусы `pending/approved/rejected` + причина.
- **BE:** очередь ручной модерации; модераторская панель (просмотр, approve/reject, причины, бан).
- **FE:** редактор анкеты, загрузка/кадрирование фото, отображение статуса модерации, подсказки по заполнению.
- **Analytics:** `profile_completed`, `photo_uploaded`, `photo_rejected`.

### Контент-политика (реализация)
- Авто-отклонение откровенного/запрещённого контента (NSFW score выше порога).
- Пограничные случаи → ручная очередь.
- Уведомление пользователю о причине отклонения + возможность загрузить другое фото.

### Acceptance Criteria
- Откровенный контент отклоняется (авто + ручная проверка); approved-фото попадают в подборку.
- Анкета валидируется (обязательные поля, возраст 18+).
- Модератор может обработать жалобу/фото из панели.

## Спринт 1.4 — Верификация и базовая безопасность

### Задачи
- **BE/ML:** селфи-верификация — liveness-проверка (моргание/поворот) + сверка с фото профиля; статус и бейдж Verified.
- **BE:** жалобы (`reports`) и блокировки (`blocks`); правила скрытия заблокированных.
- **BE:** аудит-логи доступа к ПДн (`audit_log`); ограничение прав модераторов (RBAC).
- **FE:** поток верификации (инструкция → захват селфи → результат), бейдж Verified в анкете, кнопки «пожаловаться/заблокировать».
- **Security/QA:** проверка прав доступа, хранения данных, базовый pentest, проверка флоу 152-ФЗ.

### API (пример)
- `POST /v1/verify/selfie` → запуск верификации
- `GET /v1/verify/status`
- `POST /v1/reports`, `POST /v1/blocks`

### Acceptance Criteria
- Доля верифицированных ≥60% в закрытой бете; бейдж отображается.
- Жалоба/блокировка работают; заблокированные не видны друг другу.
- Аудит-логи фиксируют доступ; RBAC ограничивает модераторов.

## Результаты стадии 1 (Deliverables)
1. Рабочее приложение: регистрация → тест → анкета → верификация (end-to-end).
2. Модераторская панель и контент-модерация (AI + ручная).
3. Функция совместимости (заготовка) с вкладом категорий.
4. Аналитика воронки онбординга.

## Definition of Done стадии / Gate
- End-to-end путь работает на stage.
- Completion онбординга ≥70%, доля верифицированных ≥60%.
- Контент-политика и базовая безопасность активны.
- Готовность к закрытой бете подтверждена QA и security-чек-листом.

## Тест-план (ключевое)
- Unit: расчёт psychoprofile и score совместимости.
- Integration: регистрация, загрузка/модерация фото, верификация.
- E2E: полный путь нового пользователя до верифицированного профиля.
- Security: RBAC, доступ к PII, OTP-лимиты.

## Риски и реакция
| Риск | Реакция |
|---|---|
| Низкий completion теста | сократить число вопросов, улучшить UX, прогресс/геймификация |
| Обход модерации | пороги NSFW + ручная очередь + переобучение |
| Слабая верификация (обход) | liveness, ручная проверка пограничных |
